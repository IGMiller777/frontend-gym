# Frontend Gym: план реализации

## Контекст

Нужен аналог SysDesign Gym (разобран в `sysdesign-gym/reverse-engineering/`), но для подготовки к frontend-собеседованиям. Исходный материал — заметки в Notion (страница «Frontend (1)»), репозиторий `/Users/gamanovichivan/Programming/Projects/frontend-gym` пуст (только `README.md`).

Решения, согласованные с вами:

- **Языки:** RU + EN с переключателем, интерфейс и весь контент.
- **Фреймворки:** React, Angular и Vue сразу в v1.
- **Режимы:** кодинг-задачи с тестами, «Что выведет код?», симулятор инцидентов, mock-интервью с ИИ.
- **Дизайн:** яркий игровой, светлая и тёмная темы, свой цвет у каждого трека.
- **Точность:** заметки считаются черновиком; каждое утверждение сверяется с официальной документацией, у каждого материала есть ссылки на первоисточник и современная практика.

### Найденные неточности (примеры, почему нужна сверка)

| Где | В заметках | На самом деле |
|---|---|---|
| TS, type vs interface | «type можно переопределять, interface нет» | Наоборот: повторное объявление `type` это ошибка, а `interface` сливаются (declaration merging) |
| TS, type guards | «`.every(x => typeof x === 'string')` не сужает тип» | С TS 5.5 предикаты типов выводятся автоматически |
| TS | `satisfies` «с 5.4», assertion functions «с 4.4» | `satisfies` с 4.9, assertion functions с 3.7 |
| TS | Примеры `Record`, `unknown`, перегрузки функции | Не компилируются (синтаксис, несовместимая сигнатура реализации) |
| Angular, Zoneless | «экспериментальный с v15, стабильный с v17» | Экспериментальный с v18, стабильный позже; проверить по angular.dev |
| Browser | Метрики FMP и TTI, HTTP/2 Server Push | FMP и TTI выведены из Lighthouse, Server Push удалён из Chrome; актуальны LCP, INP, CLS |
| System Design | FID, WCAG 2.1 | FID заменён на INP (март 2024), актуален WCAG 2.2 |
| HTML, ARIA | Ссылка на WAI-ARIA 1.0 | Актуальна WAI-ARIA 1.2 |
| Vue | `reactive(0)` «ошибка» | Предупреждение в dev и возврат исходного значения |

## Подход

Берём платформу SysDesign Gym как основу, заменяем предметные движки и добавляем три вещи, которых там нет: локализацию, обязательные источники и запуск кода в браузере.

### Локализация (RU + EN)

- Тип `Locale = 'ru' | 'en'`, выбранный язык в сторе, `<html lang>` синхронизируется, язык по умолчанию из `navigator.language`.
- **Интерфейс:** типизированные словари `src/i18n/ru.ts`, `en.ts` и хук `useT()`; числа, даты и множественное число через `Intl`.
- **Короткий контент** (задачи, карточки, дуэли, квизы): поля типа `Localized<string> = Record<Locale, string>` рядом со структурой. TypeScript не даст забыть перевод.
- **Длинный контент** (уроки, статьи): файлы `content/lessons/<id>.ru.md` и `<id>.en.md`, загрузка через `import.meta.glob` лениво по языку.
- Код, идентификаторы, ответы и ссылки общие для обоих языков.
- ИИ-эндпоинты получают `locale` и отвечают на нём.
- `check-content` проверяет паритет языков: у каждого id есть оба текста, одинаковое число секций и вопросов.

### Источники и актуальность

Каждая единица контента обязана иметь:

```ts
sources: { title: string; url: string; kind: 'official' | 'spec' | 'article' }[]  // минимум один official или spec
verified: { date: string; version?: string }  // например { date: '2026-11', version: 'React 19.2' }
```

- Список разрешённых доменов для `official`/`spec`: developer.mozilla.org, web.dev, html.spec.whatwg.org, w3.org, tc39.es, typescriptlang.org, react.dev, angular.dev, vuejs.org, rxjs.dev, router.vuejs.org, pinia.vuejs.org, nextjs.org, nuxt.com, redux-toolkit.js.org, tanstack.com, zustand.docs.pmnd.rs, mobx.js.org, ngrx.io, vite.dev, nx.dev, module-federation.io, vitest.dev, testing-library.com, playwright.dev, tailwindcss.com, nodejs.org.
- `check-content` падает, если источника нет или домен вне списка. Отдельный скрипт `scripts/check-links.ts` проверяет, что ссылки живые.
- В интерфейсе под каждым уроком, карточкой и разбором задачи блок «Источники» и метка «проверено: дата, версия».
- Устаревшие практики подаются как «раньше делали так, сейчас так» (классы → хуки, NgModule → standalone, Zone.js → signals/zoneless, Options API → Composition API, FID → INP).

### Режимы и типы заданий

| Уровень | Тип | Проверка | Основа |
|---|---|---|---|
| 1 | Вопрос с выбором ответа | мгновенно | `ChoiceTask` |
| 2 | Дуэль «что выбрать» | мгновенно | `Duel` |
| 3 | **Что выведет код?** | мгновенно | новый тип |
| 4 | Найди баг или узкое место | мгновенно | `BottleneckTask` |
| 5 | **Кодинг-задача** | тесты в браузере + ИИ-ревью | новый тип |
| 6 | Дизайн компонента или системы | ИИ по рубрике | `DesignTask` |

Плюс уроки, карточки с квизами, «объясни сам», тренировка дня, симулятор инцидентов, mock-интервью.

**Кодинг-задачи.** Редактор CodeMirror 6, TS транспилируется через `sucrase`. Логические задачи (debounce, throttle, curry, deepClone, deepEqual, memoize, EventEmitter, `Promise.all/any/race/allSettled`, mapAsyncLimit, flatten, classnames, полифилы, RxJS-операторы, сигналы) исполняются в Web Worker с таймаутом и мини-библиотекой `expect`. Компонентные задачи (React, Vue) исполняются в изолированном `iframe sandbox`, рантаймы фреймворков собраны локально, без CDN. Часть тестов скрыта. После прохождения доступно ИИ-ревью (`/api/review-code`). Эталонное решение каждой задачи прогоняется теми же тестами в CI.

Angular-компоненты в браузере требуют JIT-компилятора, это тяжело. В v1 Angular-кодинг покрывает RxJS, сигналы, DI и чистую логику; задания на шаблоны и компоненты идут как «найди баг» и ИИ-ревью. Запуск Angular-компонентов вынесен в отдельный этап.

**«Что выведет код?»** Сниппет + ожидаемые строки вывода; ответ вводом или расстановкой строк. Темы: event loop, замыкания, `this`, hoisting, прототипы, порядок эффектов React, батчинг, реактивность Vue, сигналы Angular. Каждый JS-сниппет исполняется в Vitest, и ожидаемый вывод сверяется автоматически, поэтому ошибок в ответах быть не может. Для задач на event loop пошаговый визуализатор (стек, очередь микрозадач, очередь задач, рендер): трасса записывается скриптом на инструментированном рантайме и хранится вместе с задачей.

**Симулятор инцидентов.** Детерминированный движок `src/perf/engine.ts`, по духу как `sim/engine.ts`:

- Вход: страница как набор ресурсов (HTML, CSS, JS-чанки, изображения, шрифты, сторонние скрипты) с размером, приоритетом и признаком блокировки; дерево компонентов со стоимостью и частотой рендера; профиль сети и устройства.
- Выход: TTFB, FCP, LCP, CLS, INP, TBT, размер бандла, рост памяти; пороги «хорошо» берутся из web.dev (LCP ≤ 2.5 с, INP ≤ 200 мс, CLS ≤ 0.1).
- Действия игрока: code splitting, lazy-изображения, `preload`/`fetchpriority`, `font-display`, размеры изображений, мемоизация, виртуализация, debounce, вынос в Web Worker, кэш-заголовки, CDN, сжатие, удаление стороннего скрипта, SSR или стриминг, устранение утечки.
- Игра пошаговая: ход это релиз, на ход ограниченный запас часов разработки, события (маркетинг добавил тег, релиз с регрессией, наплыв слабых устройств). Здоровье это доля пользователей с хорошими метриками.
- Каждый сценарий покрыт тестом: без действий проигрыш, эталонная стратегия выигрывает.

Сначала выпускаем упрощённую форму (задачи «найди узкое место» с водопадом загрузки и графиками), полный симулятор последним этапом.

**Mock-интервью.** Перенос существующего с тремя форматами: теория по треку (текст или голос), live-coding (редактор и тесты внутри сессии), frontend system design по RADIO (холст с блоками: клиент, CDN, BFF, API, стор, кэш, сервис-воркер, WebSocket). Три режима интервьюера и разбор по осям сохраняются; оси для system design: требования, архитектура, модель данных, API, оптимизации, коммуникация.

## Риски

- **Объём:** три фреймворка на двух языках это самый большой кусок работы. Порядок этапов позволяет получить рабочее приложение уже после этапа 2.
- **Angular в браузере:** компонентные задачи ограничены (см. выше).
- **Качество EN:** английский текст пишется вместе с русским и проходит те же проверки; термины берутся из официальной документации.
- **Свежесть:** версии библиотек меняются; метка `verified` и `check-links` показывают, что пора перепроверить.

## Проверка

- `pnpm test`: движок симулятора, раннер кода, проходимость сценариев, эталонные решения кодинг-задач, исполнение всех сниппетов «что выведет код», уникальность id и целостность пути обучения.
- `tsx scripts/check-content.ts`: паритет RU/EN, наличие официального источника и разрешённый домен, битые внутренние ссылки, словарь сокращений, стиль.
- `tsx scripts/check-links.ts`: внешние ссылки отвечают.
- `tsc -b`, `pnpm lint`, `pnpm build`: без ошибок, начальный чанк заметно меньше 3.9 МБ.
- Вручную в браузере (`pnpm dev`): пройти один модуль целиком на RU и на EN, в светлой и тёмной теме, с клавиатуры; решить кодинг-задачу; пройти задачу на event loop с визуализатором; провести короткое mock-интервью; сыграть сценарий инцидента; убедиться, что прогресс сохраняется в `data/` и переживает перезапуск.
