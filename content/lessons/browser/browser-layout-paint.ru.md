## О чём урок

Плавность интерфейса зависит от того, какие этапы рендеринга браузеру приходится повторять после изменений. Здесь разберём, что запускает layout и paint, почему чтение размера после записи стиля бывает дорогим, как анимировать без рывков и какие свойства CSS помогают браузеру. Это продолжение [урока о пути от HTML до пикселей](/learn/browser-rendering).

## Какие этапы повторяются

После изменения стиля браузер пересчитывает стили и затем повторяет только нужные этапы:

| Что меняется | Этапы | Пример свойств |
|---|---|---|
| Геометрия | style → layout → paint → composite | `width`, `height`, `margin`, `top`, `font-size`, добавление элементов |
| Только внешний вид | style → paint → composite | `color`, `background`, `box-shadow`, `border-color` |
| Слой целиком | style → composite | `transform`, `opacity` у элемента на своём слое |

Layout самый дорогой: изменение одного блока может сдвинуть соседей и пересчитать большую часть страницы. Поэтому анимации делают на `transform` и `opacity`: браузер может выполнить их в потоке компоновщика, даже когда главный поток занят.

## Принудительный синхронный layout

Обычно браузер откладывает пересчёт до следующего кадра и делает его один раз. Но если после изменения стиля код **читает** геометрию (`offsetHeight`, `getBoundingClientRect()`, `scrollTop`, `getComputedStyle`), браузеру приходится посчитать layout немедленно, чтобы вернуть верное значение. Это forced synchronous layout.

Чередование записи и чтения в цикле называют **layout thrashing**: layout считается на каждой итерации.

```js
// ❌ write, read, write, read…: one forced layout per item
for (const card of cards) {
  card.style.height = "auto"
  card.style.height = card.scrollHeight + "px"
}

// ✅ read everything first, then write everything: one layout
const heights = cards.map((card) => card.scrollHeight)
cards.forEach((card, i) => {
  card.style.height = heights[i] + "px"
})
```

Запись стиля сама layout не запускает, она только помечает его устаревшим. Дорого обходится **следующее чтение**. В DevTools это видно на вкладке Performance: фиолетовые блоки Layout с предупреждением «Forced reflow».

## Анимации без рывков

- Анимируйте `transform` и `opacity`, а не `top`, `left`, `width`.
- Для анимаций на JavaScript используйте `requestAnimationFrame`, а изменения DOM группируйте в один кадр.
- `will-change: transform` заранее выносит элемент на отдельный слой. Ставят его точечно и на время: каждый слой занимает память видеокарты, и сотни слоёв замедляют страницу. Распространённый миф: `transform: translateZ(0)` «включает GPU». Он тоже просто создаёт слой.

```css
.drawer {
  transform: translateX(-100%);
  transition: transform 200ms ease-out;
}
.drawer.open {
  transform: translateX(0);
}
```

## Свойства, которые экономят работу

- `contain: layout paint` сообщает, что изменения внутри элемента не влияют на остальную страницу, и браузер ограничивает пересчёт.
- `content-visibility: auto` пропускает layout и paint для блоков вне экрана, пока к ним не прокрутят. Вместе с ним задают `contain-intrinsic-size`, чтобы полоса прокрутки не прыгала.
- `visibility: hidden` сохраняет место элемента и не меняет раскладку соседей, а `display: none` убирает блок из раскладки, и при показе соседи сдвинутся.

## Сдвиги вёрстки

Если элемент появляется или меняет размер после первой отрисовки, содержимое под ним прыгает. Это ухудшает CLS. Основные причины и исправления:

- картинки и видео без размеров: задайте `width` и `height` или `aspect-ratio`;
- реклама и встраиваемые блоки: зарезервируйте место заранее;
- веб-шрифты, меняющие метрики текста: `font-display: swap` вместе с подобранным запасным шрифтом (`size-adjust`);
- баннеры, вставленные над контентом: показывайте их поверх или в заранее отведённом месте.

## Главное

- Геометрия запускает layout, внешний вид только paint, `transform` и `opacity` могут обойтись композицией.
- Чтение геометрии после записи стиля запускает синхронный layout; группируйте чтения отдельно от записей.
- Анимации на `transform` и `opacity`, через CSS или `requestAnimationFrame`; `will-change` точечно.
- `contain` и `content-visibility` ограничивают пересчёт; размеры медиа и резерв места спасают от сдвигов.
