## О чём урок

Доступность (a11y) значит, что интерфейсом могут пользоваться люди с разными возможностями: с клавиатурой вместо мыши, со скринридером, с плохим зрением, с увеличенным шрифтом, с чувствительностью к анимации. Для многих продуктов это ещё и требование закона: в ЕС с 28 июня 2025 года действует European Accessibility Act. Здесь основы: стандарт WCAG 2.2, доступное имя, клавиатура и фокус, контраст, движение и язык страницы.

## WCAG 2.2

Стандарт WCAG строится на четырёх принципах: контент **воспринимаемый**, интерфейс **управляемый**, всё **понятное** и **надёжное** (работает с вспомогательными технологиями). Обычно целятся в уровень AA. В версии 2.2 (2023) среди прочего добавились требования уровня AA:

- фокус не должен полностью закрываться липкой шапкой или баннером (Focus Not Obscured);
- у каждого действия перетаскиванием должна быть альтернатива без перетаскивания (Dragging Movements);
- кликабельная цель не меньше 24×24 CSS-пикселей или с достаточным отступом (Target Size);
- вход без загадок на память: можно вставить пароль и использовать менеджер паролей (Accessible Authentication).

## Доступное имя

Каждый интерактивный элемент должен иметь **доступное имя**: то, что скринридер произнесёт, и то, по чему тест найдёт элемент через `getByRole("button", { name: "Save" })`. Источники имени по приоритету: `aria-labelledby`, `aria-label`, затем нативные (`<label>` для поля, текст кнопки или ссылки, `alt` у картинки, `title` как последний шанс).

```js dom
import { computeAccessibleName } from "dom-accessibility-api"
document.body.innerHTML = `
  <button id="icon"><svg aria-hidden="true"></svg></button>
  <button id="close" aria-label="Close dialog">×</button>
  <label for="mail">Email</label><input id="mail" type="email">
  <h2 id="billing-title">Billing</h2><section id="billing" aria-labelledby="billing-title"></section>
  <a id="more" href="/post/1">Read more <span class="visually-hidden">about pricing</span></a>`
for (const id of ["icon", "close", "mail", "billing", "more"]) {
  console.log(id.padEnd(8), JSON.stringify(computeAccessibleName(document.getElementById(id))))
}
```

```output
icon     ""
close    "Close dialog"
mail     "Email"
billing  "Billing"
more     "Read more about pricing"
```

Кнопка с одной иконкой осталась без имени: скринридер скажет просто «кнопка». Браузеры используют `placeholder` как запасное имя поля без подписи, но он исчезает при вводе и не всегда озвучивается, поэтому `<label>` нужен всё равно. Визуально скрытый текст (класс `visually-hidden` с `clip` и размером в 1 пиксель, но не `display: none`) уточняет ссылки вида «Подробнее».

## Альтернативный текст

- Информативная картинка: `alt` описывает смысл, а не внешний вид: «График: выручка выросла на 20%», а не «график».
- Декоративная: `alt=""` (пустой, но присутствующий): скринридер её пропустит. Без атрибута `alt` он может прочитать имя файла.
- Картинка-ссылка или кнопка: `alt` описывает действие: «Главная», а не «логотип».

## Клавиатура и фокус

Всё, что делается мышью, должно делаться и с клавиатуры: Tab и Shift+Tab по интерактивным элементам, Enter и пробел для активации, стрелки внутри составных виджетов, Esc для закрытия.

- Порядок Tab идёт по DOM. Если визуальный порядок отличается (CSS `order`, `position`), клавиатура будет прыгать.
- `tabindex="0"` добавляет элемент в общий порядок по месту в DOM, `tabindex="-1"` позволяет фокусировать программно через `focus()`. Положительные значения ломают порядок для всей страницы, их не используют.
- Фокус должен быть **видимым**. `outline: none` без замены лишает клавиатурных пользователей ориентира. `:focus-visible` показывает обводку при навигации клавиатурой и не показывает при клике мышью.
- Ссылка «Перейти к содержимому» в начале страницы позволяет пропустить повторяющуюся навигацию.

```css
:focus-visible {
  outline: 3px solid var(--ring);
  outline-offset: 2px;
}
.skip-link:not(:focus) {
  position: absolute;
  clip-path: inset(50%);
  width: 1px;
  height: 1px;
  overflow: hidden;
}
```

## Контраст, размер, движение, язык

- Контраст текста не меньше **4,5:1**, крупного текста (от 24 px или 18,5 px жирным) **3:1**, границ полей и иконок тоже **3:1**.
- Цвет не может быть единственным признаком: ошибку показывают и текстом, а не только красной рамкой.
- Страница должна работать при увеличении до 200% и при ширине 320 px без горизонтальной прокрутки. Размеры шрифтов задают в `rem`, чтобы уважать настройки пользователя.
- `@media (prefers-reduced-motion: reduce)` отключает или упрощает анимации для людей, которых укачивает от движения.
- `<html lang="ru">` и `lang` у фрагментов на другом языке: скринридер выберет правильное произношение.

## Как проверять

Автоматические инструменты (axe DevTools, Lighthouse, `jest-axe` и `@axe-core/playwright` в тестах) находят только часть проблем: отсутствие имён, контраст, неверные атрибуты. Логику они не видят. Поэтому ещё проходят страницу клавиатурой без мыши и слушают ключевые сценарии скринридером (VoiceOver на macOS и iOS, NVDA на Windows, TalkBack на Android). В тестах компоненты ищут по роли и имени (`getByRole`): тест заодно проверяет, что у элемента есть доступное имя.

## Главное

- Цель обычно WCAG 2.2 AA; в ЕС это требование закона с июня 2025.
- У каждого интерактивного элемента есть доступное имя; иконкам нужен `aria-label` или скрытый текст.
- `alt` передаёт смысл; у декоративных картинок `alt=""`.
- Всё доступно с клавиатуры, фокус видим (`:focus-visible`), порядок Tab совпадает с визуальным, положительный `tabindex` не используют.
- Контраст 4,5:1 для текста и 3:1 для крупного и элементов управления; учитывают `prefers-reduced-motion` и `lang`.
