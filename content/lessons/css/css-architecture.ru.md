## О чём урок

Когда стилей становится много, главный вопрос уже не «как сверстать», а «как не сломать соседнее». Здесь подходы к организации CSS (соглашения об именах, CSS Modules, CSS-in-JS, utility-first), Tailwind CSS v4 и чем он отличается от v3, дизайн-токены и что на самом деле влияет на производительность CSS.

## Подходы

| Подход | Как изолирует стили | Плюсы | Минусы |
|---|---|---|---|
| BEM и другие соглашения | дисциплиной имён: `.card__title--active` | просто, без инструментов | держится на договорённостях, длинные имена |
| CSS Modules | сборщик переименовывает классы в уникальные | обычный CSS, изоляция без рантайма | общие стили и темы требуют переменных |
| CSS-in-JS в рантайме (styled-components, Emotion) | генерирует стили из JS во время работы | динамика из пропсов, всё в компоненте | стоимость в рантайме, сложности с серверными компонентами React; авторы styled-components объявили режим поддержки |
| CSS-in-JS без рантайма (vanilla-extract, Panda, StyleX) | стили из TS/JS при сборке | типизация, нет стоимости в рантайме | ещё один инструмент сборки |
| Utility-first (Tailwind) | маленькие классы на каждое свойство | быстрое прототипирование, нет мёртвого CSS, дизайн-система в конфиге | длинные списки классов, нужно знать утилиты |
| Нативные средства | `@layer`, `@scope`, вложенность | без инструментов, стандарт | меньше готовых соглашений |

Хороший ответ на собеседовании не «X лучше всех», а «чем платим»: рантайм, размер CSS, удобство тем, совместимость с SSR и серверными компонентами.

## Tailwind CSS v4

Tailwind v4 (2025) переписан, и многое из статей про v3 больше не так:

- **Подключение одной строкой**: `@import "tailwindcss";` вместо директив `@tailwind base; @tailwind components; @tailwind utilities;`.
- **Настройка в CSS**: токены задают в `@theme`, а не в `tailwind.config.js`. JS-конфиг поддерживается только явно через `@config`.
- **Сам находит файлы**: список `content` не нужен, исходники сканируются автоматически; дополнительные пути добавляет `@source`.
- **Генерирует только использованное**: PurgeCSS не нужен ни в v4, ни уже в v3 с JIT.
- **Нативный CSS внутри**: каскадные слои `theme`, `base`, `components`, `utilities`, переменные для всех токенов, `color-mix()`, цвета в `oklch`. Отсюда требования к браузерам: Safari 16.4, Chrome 111, Firefox 128.
- **Синтаксис**: модификатор важности `!` ставится в конце класса (`bg-red-500!`), свои утилиты объявляют через `@utility`, свои варианты через `@custom-variant`.

```css
@import "tailwindcss";

@theme {
  --color-brand: oklch(0.6 0.25 295);
  --font-display: "Unbounded", sans-serif;
  --breakpoint-3xl: 120rem;
}

@custom-variant dark (&:where(.dark, .dark *));

@utility text-balance-safe {
  text-wrap: balance;
}
```

Каждый токен из `@theme` становится и CSS-переменной (`var(--color-brand)`), и утилитами (`bg-brand`, `text-brand`). На этой схеме построен и сам этот тренажёр.

## Дизайн-токены

Токены это именованные значения дизайн-системы: цвета, отступы, радиусы, тени, шрифты, длительности анимаций. Обычно два уровня:

- **базовые**: палитра и шкалы (`--violet-600`, `--space-4`);
- **смысловые**: роль в интерфейсе (`--color-surface`, `--color-text-muted`, `--radius-card`).

Компоненты используют только смысловые токены. Тогда тёмная тема или ребрендинг это замена значений смысловых токенов, а не правка каждого компонента. Токены хранят в CSS-переменных, а из дизайн-инструментов (Figma Variables) их выгружают автоматически.

## Производительность CSS

- **CSS блокирует отрисовку.** Чем меньше CSS нужно до первого экрана, тем раньше FCP. Помогают разделение по маршрутам (сборщики делают это вместе с JS), встраивание критического CSS и удаление мёртвых стилей.
- **Селекторы почти никогда не проблема.** Движки оптимизировали сопоставление селекторов; «глубокие селекторы тормозят» обычно миф. Проблемы появляются на десятках тысяч элементов при частых изменениях стилей (смена класса на `<body>`, переключение темы, `:has()` высоко в дереве).
- **Дорогие свойства.** Большие `box-shadow`, `filter: blur()` и `backdrop-filter` на крупных областях дороги при перерисовке, особенно в анимации.
- **Анимации** на `transform` и `opacity`; `will-change` точечно (подробнее в [уроке о перерисовке](/learn/browser-layout-paint)).
- **Измерять, а не гадать**: в Chrome DevTools на вкладке Performance видно время Recalculate Style и Layout, а флажок «Enable CSS selector stats» в её настройках показывает, какие селекторы сколько стоят.

## Главное

- Подход выбирают по цене: рантайм, размер CSS, темы, совместимость с SSR и серверными компонентами.
- Tailwind v4: `@import "tailwindcss"`, токены в `@theme`, автоматический поиск исходников, `!` в конце класса, `@utility` и `@custom-variant`; PurgeCSS не нужен.
- Токены двух уровней: базовые и смысловые; компоненты используют смысловые.
- CSS блокирует отрисовку: меньше CSS до первого экрана; селекторы редко узкое место, измеряйте в DevTools.
