## О чём урок

«Поставил `z-index: 9999`, а модалка всё равно под шапкой» классическая ситуация, и почти всегда её причина в **контекстах наложения** (stacking contexts). Здесь как браузер решает, что рисовать поверх, что создаёт контекст наложения, типичные поломки и современный выход: верхний слой у `<dialog>` и поповеров.

## z-index работает внутри контекста

`z-index` задаёт порядок только среди элементов **одного** контекста наложения. Контекст ведёт себя как один слой: всё, что внутри, рисуется вместе с ним, и никакой `z-index` ребёнка не поднимет его выше соседа родителя.

```html
<header class="header">…</header>
<main class="page">
  <div class="modal">…</div>
</main>
```

```css
.header {
  position: sticky;
  top: 0;
  z-index: 10;
}
.page {
  position: relative;
  z-index: 1; /* creates a stacking context with level 1 */
}
.modal {
  position: fixed;
  z-index: 9999; /* compared only inside .page, so it stays below the header (10 > 1) */
}
```

`z-index` действует на элементы с `position` не `static`, а также на **flex- и grid-элементы** без всякого `position`.

## Что создаёт контекст наложения

- корень документа (`<html>`);
- `position: absolute` или `relative` с `z-index`, отличным от `auto`;
- `position: fixed` и `sticky` всегда;
- flex- и grid-элементы с `z-index` не `auto`;
- `opacity` меньше 1;
- `transform`, `filter`, `backdrop-filter`, `perspective`, `clip-path`, `mask` с любым значением, кроме `none`;
- `mix-blend-mode` не `normal`;
- `isolation: isolate`;
- `contain: layout` или `paint` (и `strict`, `content`, которые их включают);
- `will-change` с любым из этих свойств, даже пока само свойство не задано;
- элементы в верхнем слое (`<dialog>` через `showModal()`, поповеры).

Отсюда типичные поломки: плавная анимация `opacity` на обёртке или `transform` для GPU-ускорения внезапно меняют наложение всего содержимого.

## Порядок внутри контекста

Внутри одного контекста элементы рисуются слоями снизу вверх:

1. фон и рамка самого корня контекста;
2. дети с **отрицательным** `z-index`;
3. обычные блоки в потоке;
4. плавающие (`float`);
5. строчное содержимое;
6. позиционированные с `z-index: auto` или `0`, в порядке DOM;
7. дети с положительным `z-index`.

При равном `z-index` выше тот, кто позже в DOM. Отрицательный `z-index` прячет элемент под фон родителя, только если родитель сам не создаёт контекст: иначе элемент окажется над его фоном, но под содержимым. Так делают декоративные подложки через `::before`.

## Как чинить

- Найти ближайшего предка, создающего контекст (в Chrome DevTools помогает панель Layers), и поднимать `z-index` **на его уровне**, а не у ребёнка.
- Не создавать контексты случайно: убирать лишние `will-change`, `transform: translateZ(0)` и `z-index` у обёрток.
- `isolation: isolate` на компоненте явно создаёт контекст, ничего не меняя визуально: внутренние `z-index` компонента перестают конфликтовать со страницей.
- Держать небольшую шкалу значений в переменных (`--z-header: 10; --z-dropdown: 20; --z-toast: 30`) вместо гонки `9999`.

## Верхний слой

Модальные окна, меню и подсказки больше не нужно выносить в конец `<body>` и подбирать `z-index`. `<dialog>`, открытый через `showModal()`, и элементы с атрибутом `popover` попадают в **верхний слой** (top layer): он рисуется поверх всего документа, независимо от контекстов наложения и `overflow: hidden` предков. Порталы во фреймворках (`createPortal` в React, `Teleport` во Vue, CDK Overlay в Angular) решали ту же задачу до появления верхнего слоя.

## Главное

- `z-index` сравнивается только внутри одного контекста наложения; контекст ведёт себя как единый слой.
- `z-index` работает у позиционированных элементов и у flex- и grid-элементов.
- Контекст создают `opacity < 1`, `transform`, `filter`, `isolation`, `will-change`, `fixed` и `sticky`, `z-index` у позиционированных и др.
- Чинят на уровне ближайшего контекста; `isolation: isolate` изолирует компонент.
- Модалки и поповеры кладут в верхний слой через `<dialog>` и `popover`.
