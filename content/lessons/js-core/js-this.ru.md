## О чём урок

В [уроке про области видимости](/learn/js-scope-closures) значение переменной зависело от того, где код написан. С `this` всё наоборот: для обычной функции он определяется тем, **как** её вызвали. Из-за этого `this` «теряется» при передаче метода в колбэк, и это одна из самых частых тем задач «что выведет код».

Примеры урока выполняются как ES-модули, то есть в строгом режиме. В модулях и классах строгий режим включён всегда, а большинство фронтенд-кода сегодня это модули.

## Правила

| Как вызвали функцию | Чему равен `this` |
|---|---|
| `obj.method()` | `obj`, объект слева от точки |
| `fn()` | `undefined` в строгом режиме, глобальный объект в нестрогом |
| `new Fn()` | новый создаваемый объект |
| `fn.call(ctx)`, `fn.apply(ctx)`, `fn.bind(ctx)()` | `ctx` |
| стрелочная функция | `this` внешней функции, где стрелка создана; способ вызова не важен |
| обычная функция в `addEventListener` | элемент, на котором висит обработчик |

Правила проверяются сверху вниз, но с одной оговоркой: `new` сильнее `bind`. Если вызвать привязанную функцию через `new`, `this` будет новым объектом.

## Потеря контекста

Метод не «принадлежит» объекту. Если взять ссылку на функцию и вызвать её отдельно, точки слева больше нет, и `this` не будет объектом.

```js run
const user = {
  name: "Ann",
  hi() {
    return this?.name
  },
}
const hi = user.hi
console.log(user.hi(), hi())
```

```output
Ann undefined
```

То же происходит, когда метод передают как колбэк: `setTimeout(user.hi, 100)`, `button.addEventListener("click", user.hi)`, `array.map(user.hi)`. Внутри вызывается просто функция, без объекта.

## Стрелочные функции

У стрелочной функции нет собственного `this`: она берёт его из внешней функции в момент создания, как обычную переменную из замыкания. Поэтому стрелки удобны для колбэков внутри методов.

```js run
const timer = {
  label: "T",
  regular() {
    return [1].map(function () {
      return this?.label
    })[0]
  },
  arrow() {
    return [1].map(() => this.label)[0]
  },
}
console.log(timer.regular(), timer.arrow())
```

```output
undefined T
```

Обратная ловушка: стрелку нельзя делать методом объекта, если ей нужен этот объект. Объектный литерал не создаёт своего `this`, поэтому стрелка возьмёт `this` из окружающего кода (в модуле это `undefined`).

```js
const counter = {
  count: 5,
  get: () => this.count, // this здесь не counter
}
```

Изменить `this` стрелки нельзя ни `call`, ни `bind`, ни `new`: стрелку вообще нельзя вызвать с `new`.

## call, apply и bind

- `call(ctx, a, b)` вызывает функцию сразу с заданным `this` и аргументами списком.
- `apply(ctx, [a, b])` делает то же, но аргументы передаются массивом.
- `bind(ctx, a)` не вызывает функцию, а возвращает новую с навсегда привязанным `this` и, если переданы, первыми аргументами.

```js run
function greet(greeting, mark) {
  return `${greeting}, ${this.name}${mark}`
}
const ann = { name: "Ann" }
console.log(greet.call(ann, "Hi", "!"))
console.log(greet.apply(ann, ["Hello", "?"]))
const bound = greet.bind(ann, "Hey")
console.log(bound("."), bound.call({ name: "Bob" }, "."))
```

```output
Hi, Ann!
Hello, Ann?
Hey, Ann. Hey, Ann.
```

Повторный `bind` или `call` у привязанной функции `this` не меняет: побеждает первая привязка.

## this в классах

Тела классов всегда в строгом режиме, поэтому метод, переданный отдельно, получает `this === undefined` и падает при обращении к полю. Два обычных решения: привязать метод в конструкторе через `bind` или объявить его стрелочной функцией в поле класса. Стрелка в поле создаётся для каждого экземпляра и берёт `this` из конструктора.

```js run
class Button {
  label = "Save"
  handleRegular() {
    return this?.label
  }
  handleArrow = () => this.label
}
const b = new Button()
const { handleRegular, handleArrow } = b
console.log(handleRegular(), handleArrow())
```

```output
undefined Save
```

Цена стрелки в поле: она не лежит в прототипе, поэтому каждый экземпляр хранит свою копию функции, и её нельзя переопределить через `super` в наследнике.

## Главное

- `this` обычной функции определяется способом вызова, а не местом объявления.
- Ссылка на метод без объекта слева теряет `this`; в строгом режиме он становится `undefined`.
- Стрелки берут `this` из внешней функции, и изменить его нельзя.
- `call` и `apply` вызывают сразу, `bind` возвращает новую функцию; первая привязка побеждает, но `new` сильнее `bind`.
- В классах методы для колбэков привязывают через `bind` или объявляют стрелками в полях.
