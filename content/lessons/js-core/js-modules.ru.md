## О чём урок

Весь современный фронтенд собран из модулей: каждый файл с `import` и `export` это модуль. В этом уроке разберём, чем ES-модули отличаются от старого CommonJS из Node.js, что такое живые привязки, как работает динамический `import()` и почему от формата модулей зависит размер бандла.

## ES-модули

ES-модули (ESM) это стандарт языка. Модуль отличается от обычного скрипта несколькими свойствами:

- **своя область видимости:** переменные модуля не попадают в глобальную, наружу выходит только то, что экспортировано;
- **строгий режим всегда**, а `this` на верхнем уровне равен `undefined`;
- **выполняется один раз:** сколько бы файлов ни импортировали модуль, его код запустится однажды, и все получат один и тот же экземпляр;
- **статическая структура:** `import` и `export` пишутся только на верхнем уровне и не зависят от условий, поэтому граф зависимостей известен ещё до запуска;
- **`await` на верхнем уровне** разрешён.

```js run
console.log(typeof this)
console.log((function () { return typeof this })())
```

```output
undefined
undefined
```

## Живые привязки

Импорт в ESM это не копия значения, а привязка к переменной в модуле-источнике. Если модуль изменит экспортированную переменную, импортирующий код увидит новое значение. Присвоить импортированной переменной нельзя: это ошибка.

```js
// counter.js
export let count = 0
export function inc() {
  count++
}

// main.js
import { count, inc } from "./counter.js"
console.log(count) // 0
inc()
console.log(count) // 1: привязка живая
```

## Динамический import()

`import("./module.js")` загружает модуль во время работы программы и возвращает промис с объектом модуля. Сборщики (Vite, webpack) выносят такие модули в отдельные файлы-чанки, поэтому `import()` это основа разделения кода по маршрутам: `React.lazy(() => import("./Settings"))`.

В браузере модули подключают через `<script type="module">`. Такие скрипты по умолчанию загружаются с `defer` (не блокируют разбор HTML), выполняются в строгом режиме и требуют правильных заголовков CORS для файлов с других доменов.

## CommonJS

CommonJS (CJS) это формат модулей, который Node.js использовал до ESM: `require()` и `module.exports`.

| | CommonJS | ES-модули |
|---|---|---|
| Синтаксис | `require()`, `module.exports` | `import`, `export` |
| Загрузка | синхронная, `require` можно вызвать где угодно | структура статическая, `import()` для динамики |
| Что получает импортёр | объект `module.exports` из кэша; деструктуризация копирует текущие значения | живые привязки |
| `this` на верхнем уровне | `module.exports` | `undefined` |
| Браузер | только через сборщик | нативно |

В Node.js файл `.mjs` всегда ESM, `.cjs` всегда CommonJS, а `.js` определяется полем `"type"` в ближайшем `package.json`. Начиная с Node.js 22.12 (и 20.19) `require()` умеет загружать ES-модули, если в них нет `await` на верхнем уровне. CommonJS не объявлен устаревшим, но новые библиотеки и фронтенд-проекты пишут на ESM.

## Tree-shaking

Так как структура ESM статическая, сборщик видит, какие экспорты реально импортированы, и выбрасывает остальные. Это называют **tree-shaking**. С CommonJS это почти не работает: `require` может быть вызван в условии, а `module.exports` изменён во время работы.

Чтобы tree-shaking сработал, импортируйте именованно (`import { debounce } from "lodash-es"`, а не весь пакет) и следите, чтобы модули не имели побочных эффектов при импорте. Авторы библиотек сообщают сборщику, какие файлы можно безопасно выбросить, через поле `"sideEffects"` в `package.json`.

## Главное

- Модуль имеет свою область видимости, всегда строгий, выполняется один раз; `this` наверху равен `undefined`.
- Импорт это живая привязка, а не копия; присвоить импорту нельзя.
- `import()` возвращает промис и делит код на чанки.
- В Node.js тип `.js`-файла задаёт `"type"` в `package.json`; с 22.12 `require()` загружает ESM без `await` на верхнем уровне.
- Tree-shaking возможен благодаря статической структуре ESM.
