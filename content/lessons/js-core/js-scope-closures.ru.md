## О чём урок

В [прошлом уроке](/learn/js-types) мы разобрали значения. Теперь разберёмся, где живут переменные, которые эти значения хранят: в какой части кода переменная видна, что такое «всплытие» и временная мёртвая зона и как работают замыкания. Замыкания лежат в основе debounce, мемоизации, хуков React и модулей, поэтому о них спрашивают почти на каждом собеседовании.

## Лексическая область видимости

Область видимости определяет, из какой части кода доступна переменная. В JavaScript она **лексическая**: определяется тем, где переменная объявлена в тексте программы, а не тем, откуда вызвана функция. Внутренний код видит переменные внешнего, обратное неверно.

Уровней четыре:

| Уровень | Что его создаёт |
|---|---|
| Глобальный | код вне функций в обычном скрипте |
| Модульный | файл-модуль (`import` и `export`): его переменные не видны снаружи без экспорта |
| Функциональный | каждая функция |
| Блочный | любые фигурные скобки: `if`, `for`, просто `{ }` (для `let`, `const` и `class`) |

## var, let и const

`var` видна во всей функции, где объявлена, и не замечает блоков. `let` и `const` видны только внутри своего блока. `const` запрещает переприсваивание переменной, но не изменение объекта, на который она ссылается.

```js run
function demo() {
  if (true) {
    var a = 1
    let b = 2
  }
  console.log(typeof a, typeof b)
}
demo()
```

```output
number undefined
```

В обычном (не модульном) скрипте `var` на верхнем уровне ещё и становится свойством `window`, а `let` и `const` нет. В современном коде `var` не используют.

## Всплытие и временная мёртвая зона

Перед выполнением блока или функции движок заранее создаёт все объявленные в нём переменные. Это называют **всплытием** (hoisting): код как будто видит объявления раньше, чем дошёл до них. Разница в том, чем переменная заполнена до строки объявления:

- `var` уже существует и равна `undefined`;
- объявление функции (`function f() {}`) доступно целиком, его можно вызвать выше по коду;
- `let`, `const` и `class` существуют, но не инициализированы. Обращение к ним до строки объявления бросает `ReferenceError`. Этот участок кода называют **временной мёртвой зоной** (temporal dead zone, TDZ).

```js run
console.log(typeof hoisted, typeof sayHi)
var hoisted = 1
function sayHi() {}
try {
  console.log(later)
} catch (e) {
  console.log(e.name)
}
let later = 2
```

```output
undefined function
ReferenceError
```

Даже `typeof` не спасает от мёртвой зоны: `typeof later` до объявления тоже бросит `ReferenceError`, хотя для необъявленной переменной вернул бы `"undefined"`.

## Замыкание

> **Замыкание** это функция вместе со ссылкой на окружение, в котором она была создана. Функция продолжает видеть переменные этого окружения даже после того, как внешняя функция завершилась.

Каждый вызов внешней функции создаёт новое окружение, поэтому каждое замыкание получает свою копию состояния.

```js run
function makeCounter() {
  let count = 0
  return () => ++count
}
const c1 = makeCounter()
const c2 = makeCounter()
c1()
c1()
console.log(c1(), c2())
```

```output
3 1
```

Переменная `count` недоступна снаружи никак, кроме как через возвращённую функцию. Так в JavaScript делали приватное состояние задолго до появления приватных полей классов.

## Задача про цикл

Самая известная задача на замыкания: функции, созданные в цикле.

```js run
const withVar = []
for (var i = 0; i < 3; i++) withVar.push(() => i)
const withLet = []
for (let j = 0; j < 3; j++) withLet.push(() => j)
console.log(withVar.map((f) => f()).join(","), withLet.map((f) => f()).join(","))
```

```output
3,3,3 0,1,2
```

С `var` переменная `i` одна на всю функцию, все три замыкания ссылаются на неё, а к моменту вызова она равна `3`. С `let` цикл создаёт новую привязку `j` на каждой итерации, и каждое замыкание помнит своё значение. На собеседовании ту же задачу часто показывают с `setTimeout(() => console.log(i))`: причина одна и та же.

## Замыкания на практике

- **Debounce, throttle, memoize** хранят таймер или кэш в замыкании.
- **Хуки React.** Обработчик, созданный при рендере, видит значения состояния из этого рендера. Если эффект или таймер живёт дольше, он продолжает видеть старые значения: это называют устаревшим замыканием (stale closure).
- **Память.** Пока замыкание живо, живы и переменные, на которые оно ссылается. Обработчик события, который держит большой массив и не удалён, держит в памяти и массив.

## Главное

- Область видимости лексическая: решает место объявления, а не место вызова.
- `var` видна во всей функции, `let` и `const` только в блоке.
- `let`, `const` и `class` до строки объявления находятся в мёртвой зоне и бросают `ReferenceError`; `var` равна `undefined`.
- Замыкание это функция плюс окружение, где она создана; каждый вызов внешней функции даёт новое окружение.
- `let` в цикле создаёт новую привязку на каждой итерации, `var` одну на всех.
