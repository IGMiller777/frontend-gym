## О чём урок

Промис это объект-обещание результата, который появится позже: ответа сервера, прочитанного файла, истёкшего таймера. Почти всё асинхронное во фронтенде (`fetch`, `import()`, Web Crypto, ожидание анимации) возвращает промисы, а `async`/`await` из [следующих уроков](/learn/async-await) работает поверх них. Здесь разберём, как устроен промис и цепочка `then`, потому что на этом строятся и задачи «что выведет код», и реальные ошибки в обработке ошибок.

## Три состояния

Промис находится в одном из состояний:

- `pending`: результата ещё нет;
- `fulfilled`: выполнен со значением;
- `rejected`: отклонён с причиной (обычно `Error`).

Из `pending` промис переходит в одно из двух других состояний **один раз** и больше не меняется. Говорят, что он **settled** (завершён). Повторные вызовы `resolve` и `reject` игнорируются.

```js run
const p = new Promise((resolve, reject) => {
  resolve("first")
  resolve("second")
  reject(new Error("too late"))
})
p.then((value) => console.log(value))
```

```output
first
```

Функция-исполнитель, переданная в `new Promise`, выполняется **синхронно**, прямо в конструкторе. Если она бросит исключение, промис станет отклонённым. А вот колбэки `then` всегда вызываются асинхронно, как микрозадачи, даже если промис уже выполнен. Почему так, разобрано в [уроке про event loop](/learn/async-event-loop).

## Цепочка then

`then(onFulfilled, onRejected)` возвращает **новый** промис. Его судьба зависит от того, что сделал колбэк:

| Колбэк | Новый промис |
|---|---|
| вернул значение | выполнен с этим значением |
| вернул промис | повторяет его состояние, когда тот завершится |
| бросил исключение | отклонён с этим исключением |
| колбэка нет для этого случая | передаёт значение или ошибку дальше без изменений |

Поэтому цепочку пишут плоской, возвращая следующий промис из колбэка, а не вкладывая `then` в `then`.

```js run
Promise.resolve(2)
  .then((x) => x * 10)
  .then((x) => Promise.resolve(x + 1))
  .then((x) => {
    throw new Error(`bad ${x}`)
  })
  .then(() => console.log("skipped"))
  .catch((e) => {
    console.log("caught:", e.message)
    return "recovered"
  })
  .then((x) => console.log(x))
```

```output
caught: bad 21
recovered
```

Ошибка «пролетает» мимо `then` без обработчика ошибок до ближайшего `catch`. А `catch` возвращает обычный промис: если обработчик ничего не бросил, цепочка дальше идёт как успешная.

## catch и finally

- `catch(fn)` это `then(undefined, fn)`.
- `finally(fn)` вызывается в любом случае, но не получает значения и не меняет результат: значение или ошибка проходят дальше. Исключение: если `finally` сам бросит ошибку, она заменит результат.

```js run
Promise.reject(new Error("boom"))
  .finally(() => console.log("cleanup"))
  .catch((e) => console.log("still rejected:", e.message))
```

```output
cleanup
still rejected: boom
```

Разница между `then(ok, fail)` и `then(ok).catch(fail)` популярный вопрос. Во втором варианте `fail` поймает и ошибку, брошенную внутри `ok`. В первом не поймает: обработчики одного `then` не видят друг друга.

## Забытый return

Самая частая ошибка с цепочками: внутри `then` запустили асинхронную операцию, но не вернули её промис. Цепочка не ждёт её, а ошибка из неё никуда не попадёт.

```js run
const wait = (ms, v) => new Promise((r) => setTimeout(() => r(v), ms))
wait(10, 1)
  .then((x) => {
    wait(20, x + 1).then((y) => console.log("inner", y))
  })
  .then((x) => console.log("next got", x))
```

```output
next got undefined
inner 2
```

## Необработанное отклонение

Если отклонённый промис никто не обработал, браузер вызывает событие `unhandledrejection` на `window` и пишет ошибку в консоль. В Node.js по умолчанию процесс завершается с ошибкой. Поэтому у любой цепочки должен быть `catch` в конце, а у `await` должен быть `try`/`catch` где-то выше по вызовам.

## Thenable и Promise.resolve

Промисы понимают любой объект с методом `then` (thenable): `Promise.resolve(thenable)`, `await thenable` и возврат такого объекта из `then` вызовут его `then`. Так старые библиотеки промисов совместимы с нативными. `Promise.resolve(p)`, где `p` нативный промис, возвращает тот же `p`.

## Новые методы

- `Promise.withResolvers()` (ES2024) возвращает `{ promise, resolve, reject }`. Удобно, когда промис нужно завершить снаружи: из обработчика события, из очереди запросов.
- `Promise.try(fn)` (ES2025) вызывает `fn` и всегда возвращает промис: синхронная ошибка тоже превратится в отклонённый промис.

```js run
const { promise, resolve } = Promise.withResolvers()
setTimeout(() => resolve("done"), 5)
console.log(await promise)

await Promise.try(() => {
  throw new Error("sync error")
}).catch((e) => console.log("caught:", e.message))
```

```output
done
caught: sync error
```

## Главное

- Состояния: `pending`, затем один раз `fulfilled` или `rejected`.
- Исполнитель синхронный, колбэки `then` всегда асинхронные (микрозадачи).
- `then` возвращает новый промис; возвращайте из колбэка следующий промис, иначе цепочка его не ждёт.
- Ошибка идёт по цепочке до ближайшего `catch`; `finally` не меняет результат.
- Необработанное отклонение это ошибка; ставьте `catch` в конце цепочки.
