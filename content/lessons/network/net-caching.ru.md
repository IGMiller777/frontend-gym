## О чём урок

Самый быстрый запрос тот, которого не было. HTTP-кэш браузера и CDN экономит сеть и время, но неправильные заголовки дают либо вечно устаревший сайт после релиза, либо отсутствие кэша вовсе. Здесь разберём `Cache-Control`, проверку свежести через `ETag` и `304`, стратегию для разных типов файлов и кэш на уровне приложения.

## Свежий и устаревший

Ответ в кэше либо **свежий** (его можно отдать без запроса к серверу), либо **устаревший** (перед использованием его надо проверить у сервера). Сколько ответ остаётся свежим, задаёт заголовок `Cache-Control`.

| Директива | Смысл |
|---|---|
| `max-age=N` | свежий N секунд с момента ответа |
| `s-maxage=N` | то же для общих кэшей (CDN, прокси); для них перекрывает `max-age` |
| `no-cache` | хранить можно, но **каждый раз** проверять у сервера перед использованием |
| `no-store` | не сохранять вообще: для личных и чувствительных данных |
| `private` | только кэш браузера пользователя, не CDN |
| `public` | можно хранить и в общих кэшах, даже если ответ на запрос с авторизацией |
| `immutable` | не проверять, пока свежий, даже при перезагрузке (в Chrome не поддерживается, но он и так не перепроверяет свежие ресурсы при обычной перезагрузке) |
| `stale-while-revalidate=N` | ещё N секунд после устаревания отдавать старое и обновлять в фоне |

Самая частая путаница: `no-cache` не значит «не кэшировать». Это «кэшировать, но всегда спрашивать». Запрет кэша это `no-store`.

Если `Cache-Control` нет совсем, браузер может кэшировать ответ эвристически, по возрасту из `Last-Modified`. Поэтому заголовок лучше ставить всегда явно.

## Проверка: ETag и 304

Когда ответ устарел, браузер не скачивает его заново вслепую, а отправляет **условный запрос** с валидатором из прошлого ответа:

```http
GET /api/profile HTTP/1.1
If-None-Match: "v42"

HTTP/1.1 304 Not Modified
ETag: "v42"
Cache-Control: no-cache
```

Если версия не изменилась, сервер отвечает `304 Not Modified` без тела, и браузер берёт тело из кэша. Если изменилась, приходит `200` с новым телом и новым `ETag`. Вместо `ETag` может использоваться дата: `Last-Modified` в ответе и `If-Modified-Since` в запросе, но `ETag` точнее.

`Vary` перечисляет заголовки запроса, от которых зависит ответ (`Vary: Accept-Encoding`, `Vary: Accept-Language`): кэш хранит отдельную копию на каждое значение.

## Стратегия по типам файлов

| Что | Заголовок | Почему |
|---|---|---|
| JS, CSS, шрифты, картинки с хэшем в имени (`app.3f9c2a.js`) | `public, max-age=31536000, immutable` | содержимое под этим именем никогда не меняется; новая версия получит новое имя |
| HTML страниц приложения | `no-cache` (с `ETag`) | ссылки на новые хэшированные файлы должны попадать к пользователю сразу после релиза |
| Ответы API, общие для всех | `public, max-age=60, stale-while-revalidate=300` | данные можно показывать чуть устаревшими |
| Личные данные | `private, no-cache` или `no-store` | не должны попасть в общий кэш |

Сборщики (Vite, webpack) сами добавляют хэш содержимого в имена файлов. Главная ошибка этой схемы: долгий `max-age` у `index.html`. Тогда пользователи после релиза продолжают получать старый HTML со ссылками на старые файлы.

## Кэш в приложении

Поверх HTTP-кэша приложение кэширует данные само: в памяти, в библиотеках вроде TanStack Query, в Service Worker через Cache API. Два приёма встречаются везде:

- **Объединение одновременных запросов** (in-flight deduplication): если запрос за тем же ключом уже летит, второй вызов получает тот же промис.
- **Stale-while-revalidate**: сразу отдать то, что есть в кэше, и в фоне обновить.

```js run
const calls = []
const fakeFetch = (key) => {
  calls.push(key)
  return new Promise((resolve) => setTimeout(() => resolve(`${key} v${calls.length}`), 10))
}

const inflight = new Map()
const cache = new Map()

function load(key) {
  if (inflight.has(key)) return inflight.get(key)
  const promise = fakeFetch(key)
    .then((value) => {
      cache.set(key, value)
      return value
    })
    .finally(() => inflight.delete(key))
  inflight.set(key, promise)
  return promise
}

// Return the cached value at once and refresh it in the background.
function swr(key) {
  const refresh = load(key)
  return cache.has(key) ? Promise.resolve(cache.get(key)) : refresh
}

const [a, b] = await Promise.all([load("/me"), load("/me")])
console.log(a, b, "requests:", calls.length)
console.log("stale:", await swr("/me"))
await new Promise((r) => setTimeout(r, 20))
console.log("fresh:", cache.get("/me"), "requests:", calls.length)
```

```output
/me v1 /me v1 requests: 1
stale: /me v1
fresh: /me v2 requests: 2
```

Кэш в памяти ограничивают по размеру (LRU на `Map`, которая помнит порядок вставки) или по времени жизни (TTL). Иначе он растёт, пока открыта вкладка.

## Главное

- `max-age` задаёт свежесть, `no-cache` значит «проверять каждый раз», `no-store` значит «не хранить».
- Устаревший ответ проверяют условным запросом (`If-None-Match`), `304` возвращает пустое тело и разрешает взять кэш.
- Файлы с хэшем в имени кэшируют на год, HTML с `no-cache`, личные данные `private` или `no-store`.
- `Vary` разделяет копии по заголовкам запроса.
- В приложении объединяют одновременные запросы и показывают устаревшие данные, обновляя в фоне.
