## О чём урок

Фронтенд общается с сервером по HTTP, и половина проблем с загрузкой, кэшем и ошибками объясняется устройством протокола. Здесь разберём запрос и ответ, методы и их свойства, коды ответа, которые стоит знать наизусть, и чем HTTP/2 и HTTP/3 лучше HTTP/1.1 для фронтенда.

## Запрос и ответ

Запрос состоит из метода, адреса, заголовков и (не всегда) тела. Ответ из кода статуса, заголовков и тела. Адрес разбирают объектом `URL`, параметры строки запроса объектом `URLSearchParams`: он сам кодирует спецсимволы, поэтому руками склеивать строку не нужно.

```js run
const url = new URL("https://shop.example.com:8443/search?q=red+shoes&page=2#results")
console.log(url.protocol, url.hostname, url.port, url.pathname)
console.log(url.searchParams.get("q"), url.searchParams.get("page"), url.hash)
console.log(url.origin)

const params = new URLSearchParams({ q: "кофе & чай", sort: "price" })
console.log(params.toString())
```

```output
https: shop.example.com 8443 /search
red shoes 2 #results
https://shop.example.com:8443
q=%D0%BA%D0%BE%D1%84%D0%B5+%26+%D1%87%D0%B0%D0%B9&sort=price
```

`origin` это схема, хост и порт. Он определяет политику одного источника, на которой построены [CORS](/learn/net-cors) и [cookies](/learn/net-cookies-storage).

## Методы

| Метод | Назначение | Безопасный | Идемпотентный |
|---|---|---|---|
| `GET` | получить ресурс | да | да |
| `HEAD` | то же без тела | да | да |
| `POST` | создать, выполнить действие | нет | нет |
| `PUT` | заменить ресурс целиком | нет | да |
| `PATCH` | изменить часть ресурса | нет | не обязательно |
| `DELETE` | удалить | нет | да |
| `OPTIONS` | узнать возможности, предзапрос CORS | да | да |

**Безопасный** метод не меняет состояние на сервере: такой запрос можно отправить заранее, повторить или закэшировать. **Идемпотентный** метод даёт тот же результат при повторе: поэтому браузер и библиотеки могут автоматически повторить `PUT` после обрыва сети, а `POST` нет. Двойная отправка формы оплаты это как раз неидемпотентный `POST`; от неё защищаются ключом идемпотентности в заголовке.

## Коды ответа

| Код | Значение | Что делает фронтенд |
|---|---|---|
| `200`, `201`, `204` | успех, создано, успех без тела | показывает результат |
| `301`, `308` | постоянный редирект | браузер сам идёт по `Location` |
| `302`, `307` | временный редирект | то же; `307` и `308` сохраняют метод и тело |
| `304` | не изменилось | берёт ответ из кэша (см. [кэширование](/learn/net-caching)) |
| `400`, `422` | неверный запрос, ошибка валидации | показывает ошибки полей |
| `401` | не аутентифицирован | ведёт на вход или обновляет токен |
| `403` | нет прав | показывает «нет доступа», повтор не поможет |
| `404` | не найдено | страница или сообщение «не найдено» |
| `409` | конфликт версий | предлагает обновить данные |
| `429` | слишком много запросов | ждёт `Retry-After` и повторяет |
| `500`, `502`, `503`, `504` | ошибка сервера или шлюза | повторяет идемпотентные запросы с задержкой |

`401` и `403` путают чаще всего: первый про «кто вы», второй про «вам нельзя».

## HTTP/1.1, HTTP/2, HTTP/3

- **HTTP/1.1**: одно соединение обслуживает один запрос за раз. Браузер открывает до шести соединений к одному хосту, остальные запросы ждут. Отсюда старые приёмы: склейка файлов, спрайты, раздача с нескольких доменов.
- **HTTP/2**: много запросов одновременно в одном TCP-соединении (мультиплексирование), сжатые заголовки, приоритеты. Склейка и домены-шарды больше не нужны и даже мешают. Но потеря одного TCP-пакета задерживает все потоки соединения (блокировка начала очереди на уровне TCP).
- **HTTP/3**: тот же смысл поверх QUIC (UDP). Потоки независимы, потеря пакета задерживает только свой поток, соединение устанавливается быстрее и переживает смену сети (Wi-Fi → мобильная). Особенно выигрывают мобильные сети с потерями.

Протокол выбирают сервер и браузер, фронтенд-код не меняется. HTTP/2 Server Push, который был в стандарте, браузеры не поддерживают; для ранних подсказок используют `103 Early Hints` (см. [урок о загрузке](/learn/net-loading)).

## Главное

- `URL` и `URLSearchParams` разбирают и собирают адреса без ручного кодирования; `origin` это схема, хост и порт.
- Безопасные методы не меняют данные, идемпотентные можно повторять; `POST` повторять нельзя.
- `401` «войдите», `403` «нельзя», `304` «берите из кэша», `429` «подождите».
- HTTP/2 мультиплексирует запросы в одном соединении, HTTP/3 убирает блокировку TCP за счёт QUIC.
