## О чём урок

Браузер сам решает, что и в каком порядке загружать, но не знает того, что знаете вы: какая картинка главная, какой шрифт нужен сразу и куда пользователь перейдёт дальше. Здесь подсказки загрузки (`preload`, `preconnect`, `prefetch`, `modulepreload`), приоритеты, Speculation Rules, `103 Early Hints`, сжатие и CDN.

## Подсказки ресурсов

| Подсказка | Что делает | Когда использовать |
|---|---|---|
| `<link rel="preconnect" href="https://cdn.example.com">` | заранее открывает соединение: DNS, TCP, TLS | 1–3 самых важных сторонних домена; лишние соединения отнимают ресурсы |
| `<link rel="dns-prefetch" href="…">` | только DNS | для доменов «на всякий случай», дёшево |
| `<link rel="preload" href="…" as="…">` | загрузить ресурс текущей страницы с высоким приоритетом | ресурс нужен сразу, но обнаружится поздно: шрифт из CSS, LCP-картинка из CSS, данные для первого экрана |
| `<link rel="modulepreload" href="…">` | загрузить и разобрать ES-модуль со всеми зависимостями по ссылке | модули, которые понадобятся вскоре после старта |
| `<link rel="prefetch" href="…">` | загрузить с низким приоритетом для **следующей** навигации | ресурс следующей страницы |

У `preload` обязателен `as` (`font`, `image`, `style`, `script`, `fetch`): без него приоритет и проверки неверны, а ресурс скачается дважды. Шрифтам нужен ещё `crossorigin`, даже со своего домена. Если предзагруженный ресурс не использовать в первые секунды, браузер напишет предупреждение в консоль: лишний `preload` отнимает полосу у действительно важного.

## Приоритеты

Атрибут `fetchpriority="high"` или `"low"` у `<img>`, `<link>`, `<script>` и опция `priority` у `fetch` сдвигают ресурс относительно других того же типа. Главное применение: `fetchpriority="high"` у LCP-картинки (браузер иначе узнаёт, что она важная, только после раскладки) и `"low"` у картинок в карусели, которые не видны сразу.

```html
<img src="/hero.avif" width="1200" height="600" alt="…" fetchpriority="high" />
<img src="/slide-2.avif" width="1200" height="600" alt="…" loading="lazy" fetchpriority="low" />
```

## Следующая страница: Speculation Rules

Speculation Rules API описывает в JSON, какие страницы заранее загрузить (`prefetch`) или даже полностью отрисовать в фоне (`prerender`), и как рано это делать (`eagerness`: при наведении, нажатии и т. д.). Переход на заранее отрисованную страницу выглядит мгновенным.

```html
<script type="speculationrules">
  {
    "prerender": [{ "where": { "href_matches": "/products/*" }, "eagerness": "moderate" }]
  }
</script>
```

Сейчас это работает в браузерах на Chromium, `prefetch` есть в свежем Safari; остальные браузеры просто игнорируют блок, поэтому его можно добавлять без вреда. Для страниц, которые меняют данные при открытии (выход из аккаунта, корзина), prerender включать нельзя.

## 103 Early Hints

Сервер тратит время на генерацию HTML, а браузер в это время простаивает. Ответ `103 Early Hints` приходит до основного и содержит заголовки `Link` с `preload` и `preconnect`: браузер начинает загрузку стилей и шрифтов, пока сервер ещё думает. Поддерживается в Chrome, Firefox и Safari, обычно настраивается на CDN. Это замена удалённому HTTP/2 Server Push.

```http
HTTP/1.1 103 Early Hints
Link: </app.3f9c2a.css>; rel=preload; as=style
Link: <https://fonts.example.com>; rel=preconnect

HTTP/1.1 200 OK
Content-Type: text/html
```

## Сжатие

Текстовые ресурсы (HTML, CSS, JS, JSON, SVG) сжимают на сервере или CDN, браузер объявляет поддержку заголовком `Accept-Encoding`:

- `gzip` поддерживается везде;
- `br` (Brotli) сжимает текст лучше gzip, поддерживается всеми современными браузерами;
- `zstd` (Zstandard) быстрее при сопоставимом сжатии, есть в свежих Chrome, Firefox и Safari.

Статику сжимают заранее, при сборке, с максимальным уровнем; динамические ответы сжимают на лету быстрым уровнем. Картинки и видео уже сжаты своими форматами (AVIF, WebP, AV1), их повторное сжатие ничего не даёт.

## CDN

CDN держит копии ресурсов на серверах ближе к пользователю: меньше задержка, меньше нагрузка на ваш сервер. Он же завершает TLS, поддерживает HTTP/3, сжимает и отправляет Early Hints. Что и как долго хранить, CDN узнаёт из `Cache-Control` (`s-maxage` для него, `max-age` для браузера, см. [кэширование](/learn/net-caching)). После релиза ресурсы с хэшем в имени не нужно сбрасывать, а HTML и API-ответы сбрасывают (purge) или дают им короткий срок жизни.

## Главное

- `preconnect` для пары важных доменов, `preload` с `as` для поздно обнаруживаемых ресурсов, `prefetch` для следующей страницы.
- `fetchpriority="high"` у LCP-картинки, `"low"` у неважных.
- Speculation Rules заранее загружают или отрисовывают следующие страницы; не для страниц с побочными эффектами.
- `103 Early Hints` начинает загрузку, пока сервер генерирует HTML.
- Текст сжимают `br` или `zstd` с запасным `gzip`; CDN приближает ресурсы и управляется `Cache-Control`.
