## Зачем это нужно

Оператор `===` сравнивает объекты по ссылке: два разных объекта `{ a: 1 }` не равны. Сравнение по содержимому нужно в тестах (`toEqual` в Vitest и Jest), при проверке, изменились ли данные формы, при кэшировании по параметрам запроса. Задача проверяет рекурсию, знание типов и аккуратность с краевыми случаями.

## Что сделать

`deepEqual(a, b)` возвращает `true`, если значения равны по содержимому:

- примитивы сравниваются через `Object.is`: `NaN` равен `NaN`, `1` не равен `'1'`;
- массивы и обычные объекты равны, если у них одинаковые собственные перечисляемые ключи и равные по тем же правилам значения, порядок ключей не важен;
- массив не равен объекту с теми же ключами;
- даты сравниваются по времени;
- объект с лишним ключом, даже со значением `undefined`, не равен объекту без него;
- циклические ссылки не приводят к бесконечной рекурсии.

## Пример

```ts
deepEqual({ tags: ['a'], at: new Date(0) }, { tags: ['a'], at: new Date(0) }) // true
deepEqual({ a: 1, b: undefined }, { a: 1 })                                // false
```

## Идея решения

Сначала дешёвые проверки: если `Object.is(a, b)`, значения равны. Если хотя бы одно не объект или `null`, а `Object.is` уже дал `false`, они различаются.

Для объектов сравниваем прототипы: так массив не совпадёт с обычным объектом, а дата с объектом без прототипа `Date`. Даты сравниваем через `getTime()`. Дальше списки ключей: длины должны совпасть, и каждый ключ `a` должен быть собственным ключом `b` с равным значением.

Для циклов храним `Map` пар, которые уже сравниваются выше по рекурсии. Встретив ту же пару снова, считаем её равной: если где-то есть отличие, его найдёт другая ветка.

## Подводные камни

- **`JSON.stringify(a) === JSON.stringify(b)`** зависит от порядка ключей, теряет `undefined`, превращает `NaN` в `null` и падает на циклах.
- **Проверка только длины ключей.** `{ a: 1, b: undefined }` и `{ a: 1, c: undefined }` имеют одинаковую длину, поэтому нужен `Object.hasOwn(b, key)`.
- **`typeof null === 'object'`.** Без явной проверки на `null` код попытается читать его ключи.

## Что спросят дальше

- Как добавить `Map`, `Set`, `RegExp` и типизированные массивы.
- Чем `toEqual` отличается от `toStrictEqual` в Vitest: второй учитывает `undefined`-свойства и классы.
- Почему для React-пропсов используют поверхностное сравнение (`shallowEqual`), а не глубокое.
