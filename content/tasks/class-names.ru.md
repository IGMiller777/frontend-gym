## Зачем это нужно

В компонентах классы часто зависят от состояния: кнопка `active`, поле `invalid`, карточка `selected`. Собирать такую строку через `+` и тернарные операторы неудобно и легко оставить лишний пробел. Поэтому почти в каждом проекте есть утилита `classNames` (пакеты `classnames`, `clsx`). Её просят написать на собеседовании, чтобы проверить работу с типами значений, рекурсию и аккуратность.

## Что сделать

Функция `classNames(...args)` принимает любое число аргументов и возвращает строку классов через один пробел:

- строка или число добавляется как есть;
- объект добавляет свои ключи, у которых значение истинно;
- массив разбирается по тем же правилам, вложенность любая;
- ложные значения (`false`, `null`, `undefined`, `0`, `""`) и `true` пропускаются;
- в результате нет лишних пробелов в начале, в конце и между классами.

## Пример

```ts
classNames('btn', { active: isActive, disabled: false }, ['size-lg', null])
// isActive = true → 'btn active size-lg'
```

## Идея решения

Идём по аргументам и копим классы в массив, а в конце склеиваем через `join(' ')`. Так пробелы появляются только между непустыми частями.

- Первым делом отсекаем ложные значения: `if (!arg) continue`. Это сразу убирает `0`, пустую строку, `null` и `undefined`.
- Строки и числа приводим к строке.
- Массив обрабатываем рекурсивным вызовом `classNames(...arg)` и добавляем результат, только если он не пустой. Иначе пустой вложенный массив дал бы двойной пробел.
- Для объекта берём `Object.keys` и оставляем ключи с истинным значением.

## Подводные камни

- Проверка `typeof arg === 'object'` истинна и для массивов, и для `null`. Поэтому массивы проверяем раньше объектов, а `null` отсекаем первой строкой.
- `true` проходит проверку на ложность, но не подходит ни под одну ветку и тихо пропускается. Так же ведёт себя пакет `classnames`.
- Если склеивать строку прямо в цикле (`result += ' ' + cls`), придётся отдельно убирать пробел в начале.

## Что спросят дальше

- Чем `clsx` отличается от `classnames`: это совместимая замена с тем же API и меньшим размером.
- Как типизировать аргументы: рекурсивный тип `ClassValue`, как в условии задачи.
- Зачем в Tailwind-проектах поверх `clsx` используют `tailwind-merge`: он убирает конфликтующие классы вроде `p-2 p-4`.
