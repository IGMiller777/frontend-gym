## Зачем это нужно

Обход DOM-дерева лежит в основе селекторов, виртуализации, проверок доступности и инструментов тестирования. Задача проверяет, как вы обходите дерево (в глубину, в порядке документа), и знаете ли `children` и `classList`.

## Что сделать

`getElementsByClassName(root, classNames)` возвращает массив потомков `root`, у которых есть **все** классы из строки `classNames`:

- классы в строке разделены пробелами, порядок и лишние пробелы не важны;
- сам `root` не входит в результат;
- порядок документа: родитель раньше детей, соседи слева направо;
- класс сравнивается целиком, `button` не совпадает с `button-primary`;
- без `getElementsByClassName`, `querySelector` и `querySelectorAll`.

## Пример

```ts
// <div id="root"><p class="item a"></p><span class="item"></span></div>
getElementsByClassName(root, 'a item') // [p]
```

## Идея решения

Разбить строку на классы, затем обойти дерево в глубину по `element.children` (только элементы, без текстовых узлов). Для каждого потомка проверить `classList.contains` для всех классов и добавить его в результат до спуска к его детям: так получается порядок документа.

## Подводные камни

- **`childNodes` вместо `children`.** В `childNodes` есть текстовые узлы и комментарии без `classList`.
- **Поиск подстроки в `className`.** `className.includes('button')` найдёт `button-primary`; `classList` сравнивает классы целиком.
- **Корень в результате.** Встроенный метод ищет только потомков.
- **Живая коллекция.** Встроенный метод возвращает живую `HTMLCollection`, которая меняется вместе с DOM; массив это снимок.

## Что спросят дальше

- Сделайте обход без рекурсии через `TreeWalker` или явный стек.
- Напишите `getElementsByTagName` и упрощённый `querySelectorAll` для селекторов вида `div.item`.
- Чем живая `HTMLCollection` отличается от статического `NodeList` из `querySelectorAll`.
