## Зачем это нужно

Мемоизация запоминает результат чистой функции для набора аргументов и при повторном вызове берёт его из кэша. Так ускоряют дорогие вычисления: форматирование, разбор, фильтрацию больших списков. Та же идея стоит за `useMemo` в React, `computed` в Vue и Angular и селекторами в Redux. На собеседовании смотрят, как выбран ключ кэша: на этом ошибаются чаще всего.

## Что сделать

`memoize(fn)` возвращает функцию с тем же поведением, которая:

- для одинаковых аргументов вызывает `fn` один раз;
- различает `1` и `'1'`;
- сравнивает объекты по ссылке, а не по содержимому;
- кэширует и результат `undefined`;
- поддерживает любое число аргументов и различает `f(1)` и `f(1, undefined)`.

## Пример

```ts
const slowSquare = (n: number) => { /* долго считаем */ return n * n }
const square = memoize(slowSquare)
square(9) // считает
square(9) // из кэша
```

## Идея решения

Частый первый вариант: ключ `JSON.stringify(args)` или `args.join(',')`. Он ломается сразу в нескольких местах: `1` и `'1'` дают один ключ при `join`, объекты с одинаковым содержимым склеиваются, функции и `undefined` теряются, а большие объекты долго сериализуются.

Надёжнее дерево из `Map`: по уровню на каждый аргумент. `Map` сравнивает ключи по алгоритму SameValueZero, поэтому `1` и `'1'` разные, `NaN` совпадает с `NaN`, а объекты сравниваются по ссылке. Результат храним в узле под специальным ключом-символом. Признак «уже посчитано» это наличие ключа (`has`), а не истинность значения, поэтому `undefined` тоже кэшируется.

## Подводные камни

- `if (cache.get(key))` не находит закэшированные `0`, `''`, `false` и `undefined`, функция будет вызываться снова.
- Кэш без ограничения растёт бесконечно. В реальном коде ставят лимит (LRU) или кэшируют только последний вызов, как селекторы в Reselect.
- Если аргументы это объекты, `Map` держит их в памяти. Для кэша по объектам используют `WeakMap`, но в него нельзя положить примитивы.

## Что спросят дальше

- Как сделать LRU-кэш на `Map` (она помнит порядок вставки).
- Когда мемоизация вредна: дешёвые функции, нечистые функции, редкие повторы.
- Зачем мемоизировать асинхронную функцию: кэшировать сам промис, чтобы параллельные вызовы не дублировали запрос.
