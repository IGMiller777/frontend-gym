## Зачем это нужно

Сгруппировать записи по ключу и свести их в одну: заказы по пользователю, события по сессии, строки отчёта по дате. Это ежедневная работа с данными на фронтенде, и на собеседовании проверяют выбор структур данных (`Map`, `Set`) и неизменяемость.

## Что сделать

`mergeOrders(orders)` объединяет заказы одного `userId` в одну запись:

- `total` суммируется;
- `tags` объединяются без повторов и сортируются по алфавиту;
- пользователи идут в порядке первого появления во входе;
- вход не меняется.

## Пример

```ts
mergeOrders([
  { userId: 2, total: 10, tags: ['b'] },
  { userId: 1, total: 5, tags: [] },
  { userId: 2, total: 1, tags: ['a', 'b'] },
])
// [{ userId: 2, total: 11, tags: ['a', 'b'] }, { userId: 1, total: 5, tags: [] }]
```

## Идея решения

`Map` от `userId` к накопителю: `Map` помнит порядок вставки, поэтому порядок первого появления получается сам. Теги копим в `Set`, в конце превращаем в отсортированный массив и собираем новые объекты.

## Подводные камни

- **Мутация входа.** Если накапливать в первом найденном объекте (`existing.total += …`), изменится исходный массив.
- **Порядок через объект.** У обычного объекта ключи-числа сортируются по возрастанию, и порядок первого появления потеряется; `Map` его сохраняет.
- **Дубликаты внутри одной записи.** Теги нужно дедуплицировать и для пользователя с одним заказом.
