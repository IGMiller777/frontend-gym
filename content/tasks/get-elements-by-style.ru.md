## Зачем это нужно

Найти элементы по стилю нужно в инструментах (проверки контраста, аудит шрифтов, поиск скрытых элементов) и тестах. Задача проверяет разницу между встроенным стилем (`el.style`) и вычисленным (`getComputedStyle`) и умение сравнивать значения CSS, записанные по-разному.

## Что сделать

`getElementsByStyle(root, property, value)` возвращает потомков `root`, у которых **вычисленное** значение свойства `property` равно `value`:

- учитываются встроенные стили, правила из таблиц стилей и наследование;
- значение сравнивается в нормализованном виде: `red` совпадает с `rgb(255, 0, 0)`, `bold` с `700`;
- сам `root` не входит, порядок документа.

## Пример

```ts
// <div style="color: green"><span></span></div>
getElementsByStyle(root, 'color', 'green') // [div, span]: color is inherited
```

## Идея решения

Чтобы сравнивать значения в одной форме, искомое значение прогоняем через тот же механизм: создаём временный элемент, ставим ему `property: value`, добавляем в документ, читаем вычисленное значение и удаляем элемент. Затем обходим потомков и сравниваем `getComputedStyle(el).getPropertyValue(property)` с нормализованным значением.

## Подводные камни

- **`el.style` видит только атрибут `style`.** Правила из CSS и наследуемые значения в нём отсутствуют.
- **Сравнение строк как есть.** Браузер возвращает цвета в `rgb()`, жирность числом, размеры в `px`; `'red' === 'rgb(255, 0, 0)'` ложно.
- **Элемент вне документа.** У отсоединённого элемента вычисленных стилей нет, поэтому временный элемент добавляют в документ.
- **Производительность.** `getComputedStyle` для тысяч элементов дорогой: он может вызвать пересчёт стилей. В реальных инструментах проверяют пачкой и не перемежают чтение с записью.

## Что спросят дальше

- Как найти невидимые элементы: `display: none`, `visibility: hidden`, нулевой размер, `opacity: 0`.
- Почему чтение стилей после записи вызывает принудительный пересчёт (layout thrashing).
- Как получить стили псевдоэлемента (`getComputedStyle(el, '::before')`).
