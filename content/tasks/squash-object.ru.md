## Зачем это нужно

Плоский вид вложенных данных нужен постоянно: ключи переводов (`errors.email.required`), поля форм в библиотеках форм, логирование, сравнение конфигураций, отправка фильтров в query-строку. Задача проверяет рекурсивный обход и аккуратную работу с краевыми случаями.

## Что сделать

`squash(value)` возвращает новый объект в один уровень, где ключ это путь через точку:

- вложенные объекты разворачиваются: `{ a: { b: 1 } }` → `{ 'a.b': 1 }`;
- массивы обходятся по индексам: `{ tags: ['x'] }` → `{ 'tags.0': 'x' }`;
- пустой ключ не добавляет сегмент пути: `{ a: { '': 1 } }` → `{ a: 1 }`;
- `null`, `undefined` и даты остаются значениями, пустые объекты и массивы исчезают;
- вход не меняется.

## Пример

```ts
squash({ user: { name: 'Ann', roles: ['admin'] }, active: true })
// { 'user.name': 'Ann', 'user.roles.0': 'admin', active: true }
```

## Идея решения

Рекурсивная функция `walk(node, path)`: если узел объект или массив, обходим `Object.entries` и спускаемся, добавляя ключ к пути (пустой ключ пропускаем); иначе записываем значение по ключу `path.join('.')`.

## Подводные камни

- **`typeof null === 'object'`.** Без проверки на `null` рекурсия упадёт на `Object.entries(null)`.
- **Даты и другие экземпляры.** `Object.entries(new Date())` пустой, и дата бесследно исчезнет. Значения, которые не обычные объекты и не массивы, записывают как есть.
- **Конкатенация строк для пути.** Сборка `prefix + '.' + key` даёт лишнюю точку в начале или при пустом ключе; массив сегментов и `join` проще.
- **Циклы.** Объект со ссылкой на себя уведёт рекурсию в переполнение стека; если такие данные возможны, путь хранят в `WeakSet`.

## Что спросят дальше

- Напишите обратную функцию `unsquash`: из путей обратно во вложенный объект (и когда сегмент-число означает массив).
- Как экранировать точки внутри самих ключей.
- Как сделать обход без рекурсии, на явном стеке.
