## Зачем это нужно

Загрузить 200 файлов или отправить 500 запросов к API одним `Promise.all` плохая идея: браузер ограничивает число соединений к одному хосту, сервер может ответить ошибкой 429, а интерфейс подвиснет. Нужен пул: работает не больше N задач одновременно, и как только одна закончилась, начинается следующая. Это частая задача на собеседованиях уровня middle и senior.

## Что сделать

`mapLimit(items, limit, mapper)`:

- вызывает `mapper(item, index)` для каждого элемента, одновременно выполняется не больше `limit` вызовов;
- освободившееся место сразу занимает следующий элемент, без ожидания всей пачки;
- разрешается массивом результатов в порядке `items`;
- при первой ошибке отклоняется ей и больше не запускает новые элементы;
- синхронная ошибка внутри `mapper` обрабатывается так же, как отклонённый промис;
- `limit` положительное целое число.

## Пример

```ts
const pages = await mapLimit(urls, 4, (url) => fetch(url).then((r) => r.text()))
```

## Идея решения

Представим `limit` «работников». Каждый берёт следующий необработанный индекс (`next++`), ждёт его результат и сразу берёт следующий. В начале запускаем `min(limit, items.length)` работников. Когда завершены все элементы, разрешаем общий промис.

Почему не пачками: `for` по кускам с `await Promise.all(chunk)` ждёт самый медленный элемент в каждой пачке. С длительностями `[100, 10, 10, 10]` и лимитом 2 пачки закончатся через 110 мс, а пул через 100 мс, и второе место не простаивает.

Вызов `mapper` обёрнут в `try`, а результат в `Promise.resolve`: так синхронный `throw` и обычное значение обрабатываются как промисы.

## Подводные камни

- **Порядок.** Результаты кладём по индексу, а не через `push`.
- **Остановка на ошибке.** Флаг `failed` не даёт запускать новые элементы. Уже запущенные доработают: промисы нельзя отменить без `AbortController`.
- **Пустой список.** Без отдельной проверки промис не разрешится.

## Что спросят дальше

- Как передать `AbortSignal` в `mapper` и отменять запущенные запросы при первой ошибке.
- Как добавить повторы с экспоненциальной задержкой для ошибок 429 и 503.
- Как сделать то же через асинхронный итератор, чтобы обрабатывать бесконечный поток.
