## Зачем это нужно

`reduce` сводит массив к одному значению: сумма, объект-индекс, группировка, сборка строки. Полифил `reduce` классическая задача: она проверяет, понимаете ли вы, что метод делает без начального значения, как обходит дыры в массиве и что передаёт колбэку.

## Что сделать

`reduce(array, callback, initial?)` работает как `array.reduce(callback, initial)`:

- колбэк получает `(acc, value, index, array)`;
- без начального значения аккумулятор равен первому существующему элементу, обход начинается со следующего;
- на пустом массиве без начального значения бросается `TypeError`;
- дыры (`[1, , 3]`) пропускаются;
- `initial`, переданный явно как `undefined`, это тоже начальное значение.

## Пример

```ts
reduce([1, 2, 3], (sum, x) => sum + x, 10) // 16
reduce([1, 2, 3], (sum, x) => sum + x)     // 6, callback called for indexes 1 and 2
reduce([], (a, b) => a + b)                // TypeError
```

## Идея решения

Сначала решаем, откуда взять аккумулятор: из `initial`, если он передан, иначе из первого существующего элемента (пропустив дыры в начале). Затем идём по индексам до исходной длины и вызываем колбэк только для индексов, которые есть в массиве (`i in array`).

## Подводные камни

- **«Не передан» и «передан `undefined`» разные вещи.** Параметр по умолчанию их не различит, поэтому сигнатура `...initial` и проверка `initial.length`.
- **Дыры.** `array[i]` для дыры даёт `undefined`, и сумма станет `NaN`. Проверка `i in array` отличает дыру от явного `undefined`.
- **Длина фиксируется в начале.** Если колбэк добавит элементы, встроенный `reduce` их не обойдёт.
- **Проверка колбэка.** `reduce([1], 'x')` должен бросить `TypeError`, а не упасть позже с непонятной ошибкой.
