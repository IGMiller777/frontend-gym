## Зачем это нужно

Оптимистичный интерфейс показывает результат действия сразу, не дожидаясь сервера, и откатывает его при ошибке. В React 19 для этого есть `useOptimistic`, и задача проверяет, понимает ли кандидат Actions: асинхронные переходы, временное значение и откат без ручного «вернуть как было».

## Что сделать

`<LikeButton liked count save />`:

- кнопка «Like» с `aria-pressed`, рядом текст «N likes»;
- по клику новое состояние (нажата или нет, счётчик ±1) видно сразу, затем вызывается `save(liked)`;
- если `save` выполнился, состояние остаётся; если отклонён, кнопка и счётчик возвращаются к прежним значениям и появляется «Could not save»;
- следующий успешный клик убирает сообщение.

## Идея решения

Настоящее (подтверждённое) состояние хранится в `useState`, а показывается `optimistic` из `useOptimistic(state)`. Клик запускает Action через `startTransition(async () => ...)`: внутри сначала `setOptimistic(next)`, и интерфейс сразу показывает новое значение, потом `await save(...)`.

- При успехе `setState(next)`: когда Action закончится, `optimistic` снова равен настоящему состоянию, а оно уже новое.
- При ошибке настоящее состояние не трогаем: Action закончился, временное значение исчезло само, откатывать вручную нечего. Остаётся показать сообщение.

Обновления после `await` снова оборачиваются в `startTransition`: в текущей версии React контекст перехода после `await` теряется.

## Подводные камни

- **Обновить после ответа.** `await save(); setState(next)` честно, но не оптимистично: пользователь ждёт сервер.
- **Обновить сразу без отката.** `setState(next); save()` оптимистично, но при ошибке интерфейс врёт.
- **`setOptimistic` вне Action.** Вне перехода React предупредит, а значение не будет временным.
- **Action, который не завершается.** Пока асинхронный Action в работе, React объединяет с ним новые переходы, поэтому зависший запрос задерживает и другие обновления. У `save` должен быть тайм-аут.

## Что спросят дальше

- Чем это отличается от `useActionState` с формой: там есть очередь вызовов и прошлое состояние в аргументе.
- Как не дать кликать, пока сохраняется (`useTransition` и `isPending`), и стоит ли это делать.
- Как это устроено в TanStack Query: `onMutate` с ручным снимком кэша и откат в `onError`.
