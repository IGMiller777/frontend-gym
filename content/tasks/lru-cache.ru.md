## Зачем это нужно

LRU (least recently used) кэш хранит ограниченное число записей и при переполнении выбрасывает ту, к которой дольше всего не обращались. Так устроены кэши запросов, изображений, вычислений и браузерный кэш страниц. Задачу дают, чтобы проверить выбор структуры данных: обе операции должны работать за O(1).

## Что сделать

Класс `LRUCache(capacity)`:

- `get(key)` возвращает значение или `undefined` и делает запись самой свежей;
- `set(key, value)` добавляет или обновляет запись (обновление тоже делает её самой свежей); при превышении `capacity` удаляется самая давняя запись;
- `size` возвращает число записей;
- ключи любого типа, включая объекты; значения любые, включая `null`;
- `get` и `set` за O(1).

## Пример

```ts
const cache = new LRUCache<string, number>(2)
cache.set('a', 1)
cache.set('b', 2)
cache.get('a')    // 1, a is now the most recent
cache.set('c', 3) // evicts b
cache.get('b')    // undefined
```

## Идея решения

`Map` перебирает ключи в порядке вставки. Если при каждом обращении удалять запись и вставлять её заново, она окажется в конце, а в начале останется самая давняя. Переполнение: удалить `map.keys().next().value`. Все операции `Map` в среднем O(1).

## Подводные камни

- **Обновление существующего ключа.** `set` для уже существующего ключа без `delete` оставит запись на старом месте, и её выбросят первой.
- **Проверка через `get`.** `if (map.get(key))` ошибается на значениях `0`, `''`, `null`; нужен `has`.
- **Массив для порядка.** `indexOf` и `splice` по массиву ключей дают O(n) на операцию.
- **Без `Map` с порядком вставки** (например, в других языках) LRU собирают из хеш-таблицы и двусвязного списка: таблица находит узел, список перемещает его в голову за O(1).
