## Зачем это нужно

`call`, `apply` и `bind` задают `this` при вызове. Написать `call` без них значит понимать главное правило `this`: при вызове `obj.method()` внутри `this` равен `obj`. Задачу дают, чтобы проверить это правило, `Symbol` и аккуратность с побочными эффектами.

## Что сделать

`callWith(fn, thisArg, ...args)` вызывает `fn` с `this === thisArg` и аргументами `args` и возвращает результат:

- без `fn.call`, `fn.apply`, `fn.bind` и `Reflect.apply`;
- `thisArg` равный `null` или `undefined` означает обычный вызов;
- объект после вызова остаётся таким же, как был, даже если `fn` бросила ошибку;
- существующие свойства объекта не затираются.

## Пример

```ts
function greet(greeting: string) {
  return `${greeting}, ${this.name}`
}
callWith(greet, { name: 'Ann' }, 'Hi') // 'Hi, Ann'
```

## Идея решения

Временно кладём функцию в объект под уникальным ключом `Symbol()` и вызываем её как метод: `target[key](...args)`. При вызове через точку `this` указывает на объект. В `finally` удаляем временное свойство.

## Подводные камни

- **Ключ-строка затрёт чужое свойство.** `obj.fn = fn` сломает объект, у которого уже есть `fn`. Символ гарантированно уникален и не виден в `Object.keys`.
- **Уборка при ошибке.** Без `finally` исключение оставит временное свойство на объекте.
- **Примитивы.** К строке или числу свойство не добавить, поэтому `Object(thisArg)` упаковывает их в объект-обёртку. Настоящий `call` передаёт примитив как есть: в строгой функции `typeof this` останется `"string"`, а у нас будет `"object"`. Повторить это без встроенных средств нельзя.
- **Замороженный объект.** На `Object.freeze(obj)` свойство не добавится. Обойти можно через `Object.create(obj)`: `this` тогда будет наследником, а не самим объектом.
