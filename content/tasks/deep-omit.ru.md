## Зачем это нужно

Убрать служебные или секретные поля перед логированием или отправкой данных: `password`, `token`, `__typename`, `_id`. Поля бывают на любой глубине, в том числе внутри массивов объектов. Задача проверяет рекурсию и неизменяемые обновления.

## Что сделать

`deepOmit(value, keys)` возвращает копию `value` без ключей из `keys` во всех вложенных обычных объектах и массивах:

- примитивы возвращаются как есть;
- массивы обходятся поэлементно;
- вход не меняется.

## Пример

```ts
deepOmit({ id: 1, password: 'x', items: [{ password: 'y', ok: true }] }, ['password'])
// { id: 1, items: [{ ok: true }] }
```

## Идея решения

Рекурсивный обход с тремя ветками: массив (`map` по элементам), обычный объект (новый объект без запрещённых ключей, значения обходятся рекурсивно), всё остальное возвращаем как есть. Ключи складываем в `Set`, чтобы проверка была за O(1).

## Подводные камни

- **Мутация.** `delete obj.password` на входном объекте испортит данные у вызывающего кода.
- **Даты, `Map` и экземпляры классов.** Если обходить их как обычные объекты, получится пустой `{}` вместо даты. Обходят только обычные объекты.
- **`keys.includes` в цикле.** Для большого списка ключей и больших данных это O(n·m); `Set` даёт O(1) на проверку.
